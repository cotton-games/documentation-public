## Audit des 14 points demandés

1. **Clic Master** : `games/web/modules/app_hub_view_helpers.php`, `games_hub_render_program()` produit la carte et `setAction()` projette son action vers le bouton central. Son listener `action.addEventListener('click', ...)` poste `launch_session` sur la page Hub ; `games_hub_handle_play_action()` appelle `app_games_hub_session_launch_from_master()`. Le lien `Reprendre` reste un lien ; le résolveur `games_hub_master_card_action_resolve()` exclut toujours l’officiel papier avant les branches focus/runtime.
2. **Clic Remote** : `games/web/modules/app_hub_remote_ajax.php`, `bindLaunchButtons()` appelle `submitLaunchSession()` (ou le sas papier existant). Le POST `launch_session` crée une commande par `app_games_hub_remote_command_create()` ; le poll/claim Master existant finit dans `games_hub_handle_master_remote_launch_command()` puis le même lanceur Global. Aucun dialogue dans le consommateur de commande.
3. **Frontière de mutation** : sur Remote, la queue est déjà une écriture, avant le lancement ; le sas papier lit/prépare aussi son roster via ses actions existantes. Sur Master, l’effacement d’intention de sélection et `showHubPodium()` précèdent le POST. Dans Global, le lanceur prépare éventuellement la session historique papier, écrit le focus officiel, prépare/réutilise le runtime et écrit `hub_execution_started` ; ce n’est pas une unique mutation atomique. On intercepte donc avant toutes ces opérations, pas entre elles.
4. **Insertion** : après validation locale de l’action et du session_id, avant tout effet du clic. Remote : avant `openPaperLobby()` comme avant `submitLaunchSession()`. Master : avant label Lancement, clear selection, podium, génération d’intention et fetch. Après attente : revalidation de disponibilité/instance et identité de l’action ; Remote rejette notamment un bouton remplacé par le snapshot.
5. **Consommation canonique Hub** : preuve existante `games_hubs.player_qr_official_started_at`, renseignée par `app_games_hub_player_qr_official_launch()` / `app_games_hub_player_qr_launch_reduction(..., true)` après succès officiel ; une démo utilise false et ne date pas le premier officiel. `app_games_hub_get_by_id()` charge la ligne entière, la normalisation conserve cette colonne. Pas de helper booléen Hub pur trouvé : `games_hub_has_official_launch($hub, $sessions)` est une projection Games en lecture seule. Il réutilise la trace, puis les indicateurs `hub_has_started` officiels déjà produits par `app_games_hub_sessions_get()` en repli pour les anciens Hubs. Ces indicateurs viennent de `app_games_hub_session_has_started()` ; `app_games_hub_session_last_launches_get()` exclut les événements de démo. Calcul une fois par projection Master/Remote, aucune requête supplémentaire, pas de récupération QR ni d’écriture. La trace survit à la suppression d’une session. Si stockage absent et plus aucune preuve dans les sessions chargées, absence de preuve = confirmation conservée ; aucune donnée runtime inventée. Une officielle lancée/terminée/suspendue dispense toutes les suivantes ; les gardes par session continuent seulement d’exclure Reprendre/Relancer. Aucun agrégat DOM/JS. Source documentaire : [README Global raw](https://raw.githubusercontent.com/cotton-games/documentation-public/refs/heads/develop/canon/repos/global/README.md), « Update 2026-09-07 — Hub : compteur confirmé et persistance du QR joueurs », première date officielle conservée, démos sans date. Le helper booléen de projection Hub : non trouvé dans la documentation avant cet ajustement.
6. **Historique** : `boot_organizer.js`, `handleSessionMetaBeforePlay()`, confirmation officielle via SweetAlert2. `remote/remote-ui.js`, `showSessionStart()`, possède une variante avec Annuler ; elle reste intacte. Le pattern Organizer est retenu pour les deux surfaces Hub.
7. **Wording et annulation** : pour Hub uniquement, titre « Démarrer la soirée maintenant ? », texte « ⚠️ Une fois une session officielle lancée, elle ne peut plus être redémarrée. » puis « Si tu souhaites d’abord vérifier le fonctionnement, tu peux lancer un test. », CTA « ✅ Oui, démarrer ». Identique papier/numérique. Croix et Échap ; clic extérieur ignoré ; aucun bouton Annuler ajouté. Le titre et les hooks du diagnostic de l’Organizer historique restent inchangés. La mention du test papier en numérique demeure sur les surfaces existantes.
8. **Réutilisation locale** : `launch_confirmation.js` fournit les options communes utilisées aussi par l’Organizer historique, plus la fonction de confirmation Hub. SweetAlert2 et les classes historiques sont conservés ; CSS de modale historique repris dans une feuille limitée aux pages Hub Master/Remote, sans charger le layout Canvas. Texte Hub unique demandé, sans variante papier. Verrou anti-double clic en mémoire de la page, aucun état partagé, storage, Bus, poll ou timer. Échap ne ferme pas le podium Hub pendant que SweetAlert est visible.
9. **QR papier parasite** : `boot_organizer.js`, bloc 6b « Hint remote obligatoire en version papier ». Avant patch : papier serveur + desktop >=992 + remoteUrl + ClientSessionMeta.isOpen + aucune Remote secondaire, puis attente du diagnostic et SweetAlert QR. Aucune vérification d’autorité Hub. Le garde commun précède désormais cette branche ; le breakpoint mobile reste identique.
10. **Boot diagnostic** : `prelaunch_check.js`, `initPrelaunchCheck()`, initialise état/listeners réseau/WS/store puis `auto_precheck` lorsque pending/ouvert ; le retour du store à pending déclenche `auto_precheck_resume`. Les résultats passent par l’auto-ouverture de modale. Le garde sort avant cette initialisation automatique pour une officielle orchestrée ; l’entrée manuelle `showPrelaunchModal()` n’est pas supprimée.
11. **Garde premier lancement préexistant** : `boot_organizer.js`, `beginPlayFlow({source:'hub'})`, bypass du blocage prelaunch et `autoConfirmed=true` pour la confirmation historique ; annulation du diagnostic lors du lancement.
12. **Pourquoi reprise non couverte** : le boot du diagnostic/QR est indépendant de `beginPlayFlow` ; la reprise pausée n’appelle volontairement pas l’auto-play. Le bypass attaché à l’action n’empêchait donc pas ces boots. Le patch rend aussi `prelaunchRequiredForLaunch=false` sous autorité officielle Hub, pour éviter de réouvrir le diagnostic par un contrôle de reprise.
13. **Autorité canonique** : helper pur `isOfficialHubOrchestrated()` : `AppConfig.hubOrganizer.enabled === true`, runtimeMode officiel, executionId non vide, sourceSessionId positif et égal à runtimeSessionId. `organizer_canvas.php` produit ce contexte depuis l’exécution ouverte Global, avec exclusion du Master individuel terminal ; le token Hub seul ne l’active pas. Pas de nouveau marqueur, ni écriture, ni inspection d’URL. Une démo annexe ne peut pas autoriser le runtime source officiel avec ce garde. Historique autonome / Dashboard mobile sans exécution Hub restent historiques, même avec membership Hub. Une exécution officielle ouverte déjà reconnue par le resolver reste sous l’autorité existante ; aucune réinterprétation de ce resolver ni réparation d’événements anciens dans ce patch.
